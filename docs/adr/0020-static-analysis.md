# 0020 · Static analysis in the build: Checkstyle, PMD/CPD and SpotBugs

- **Status:** accepted · 2026-11-24 (decided by the user after the Clean Code course analysis, #168)
- **Issue:** #168 · **Related:** #166 (test names), #167 (magic numbers), [ADR 0009](0009-domain-without-lombok.md) (no Lombok in the domain)

## Context

Until this ADR the project had no static analyser: only the compiler, ArchUnit (`HexagonalArchitectureTests`, `DomainIsolationTests`), `check-domain.mjs` (Lombok and Immutables out of the domain) and the contract checks (Redocly, oasdiff, Schemathesis). The user follows a Clean Code course whose chapter 25 presents Checkstyle, PMD/CPD, SpotBugs and SonarQube, and whose base project (Lab 3.5) brings a `checkstyle.xml` and a `pmd-ruleset.xml`.

On 2026-11-24 the course's rules and versions were run locally on a scratch copy of the project:

| Tool | Warnings | Production | What they were |
| ---- | -------: | ---------: | -------------- |
| Checkstyle | 1,080 | 19 | 813 naming warnings in tests (Spanish `snake_case`, fixed in #166) and 19 magic numbers in production (fixed in #167); 248 numbers in tests |
| PMD | 9 | 8 | `GodClass` and `CouplingBetweenObjects` in `CheckingAccountService` and `AccountWebController`, `GodClass` in `CheckingAccount`, `CyclomaticComplexity` in `CheckingAccount.reconstitute` and in two `validate()` |
| CPD | 1 | 0 | 14 repeated lines in `AccountControllerTests` |
| SpotBugs | 23 | 23 | 15 false positives (code generated by Immutables, a JPA field), 4 `CT_CONSTRUCTOR_THROW`, 4 real bugs |

The course's guidelines for adopting these tools: start with few rules, agree them as a team and keep them in the repository, require the level of new code instead of fixing everything at once, never get used to warnings nobody reads, and combine tools because each one finds different things.

## Decision

- **Three tools, in `./mvnw verify`.** Their `check` goals are bound to the `verify` phase, so a violation fails the local build and the CI (which already runs `./mvnw -B verify`) with no new step:
  - **Checkstyle** (maven-checkstyle-plugin 3.6.0, Checkstyle 14.3.0): the course's naming rules (`PackageName`, `TypeName`, `MethodName`, `ConstantName`, `MemberName`, `ParameterName`, `LocalVariableName`, `AbbreviationAsWordInName`) and `MagicNumber`, on production and test code. `MagicNumber` is suppressed in `src/test`: numbers there are test data and read better as literals.
  - **PMD + CPD** (maven-pmd-plugin 3.28.0, PMD 7.17.0): the course's four design rules (`GodClass`, `CouplingBetweenObjects`, `ExcessiveParameterList`, `CyclomaticComplexity`), on production and test code, and CPD for copy-paste.
  - **SpotBugs** (spotbugs-maven-plugin 4.10.5.0): its default detectors on the bytecode.
- **Baseline for PMD.** The 9 design smells that already exist (8 in production, 1 in a test) are listed in `pmd-baseline.properties` (`excludeFromFailureFile`), with a comment each: they do not fail the build and the plugin also leaves them out of the report (`-Dpmd.baseline=` shows them), any new one fails the build, and refactoring them is left to their own issues (`pendientes.md`).
- **Narrow, commented exclusions for SpotBugs** (`spotbugs-exclude.xml`), never a whole package or category:
  - `AT_STALE_THREAD_WRITE_OF_PRIMITIVE` and `EI_EXPOSE_REP` in the classes Immutables generates: its `InitShim` is used by one thread while building one object, and its lists are already unmodifiable copies. Generated code cannot be fixed: it is rewritten on every build.
  - `URF_UNREAD_FIELD` in the JPA entities of the output adapters (`adapter.out..*Entity`): Hibernate reads those fields by reflection.
- **Real findings are fixed, not excluded:** the 4 `CT_CONSTRUCTOR_THROW` (3 domain classes that validate in the constructor become `final`; `Transaction` had two constructors), and the 4 bugs (a possible `null` from `queryForObject`, two reboxings, a `SecureRandom` used once). The CPD duplicate is extracted to a helper.
- **A false positive found later** is handled the same way: a narrow exclusion with a comment saying why, never a habit of ignoring the warning.

## Alternatives

- **SonarQube** (course, section 25.5): history, quality gate and more rules, but it needs a server (or SonarQube Cloud) and a token in the CI. It is recommended as **SonarQube for IDE** on the user's machine, which needs nothing in the repository.
- **Error Prone:** probable bugs during compilation. It overlaps with SpotBugs and hooks into the compiler next to the Lombok and Immutables processors; left out to keep the build simple.
- **Reports only, without failing the build:** less friction, but the course warns that warnings nobody is forced to read end up ignored.
- **The course's rules as they are, without exclusions or baseline:** the build would fail from the first day on code generated by Immutables, on JPA entities and on smells that need their own refactoring.

## Consequences

- `./mvnw verify` takes about **8 s longer** (measured on 2026-11-24, two rounds on the same code: 64 → 69 s and 51 → 62 s). For a quick local run the four can be skipped with `-Dcheckstyle.skip -Dpmd.skip -Dcpd.skip -Dspotbugs.skip`; never in the CI.
- New code must pass the three tools; Claude's skills and agents run `./mvnw verify` as the "done" check, so they get the same feedback.
- HTML reports, for reading and for the course: `./mvnw checkstyle:checkstyle pmd:pmd pmd:cpd spotbugs:spotbugs` (in `target/reports` and `target/spotbugsXml.xml`), and `./mvnw spotbugs:gui`. `-Dpmd.baseline=` turns the baseline off, so the PMD report also lists the smells that already existed (with it, the plugin leaves them out of the report too).
- The PMD baseline works by class and rule, not by method: a new `CyclomaticComplexity` in another method of `CheckingAccount`, or more coupling in a listed class, would not fail the build. It is a limit of the plugin; the refactoring issues in `pendientes.md` remove those entries. Since #182 the baseline has no entries (#174, #177, #181 and #182 removed them), so the limit no longer applies.
- The SpotBugs exclusion matches the generated classes by their `@org.immutables.value.Generated` annotation, so a new Immutables value type needs no change. Checkstyle, PMD and CPD are limited to `src/main/java` and `src/test/java` (they would otherwise read `target/generated-sources` at `verify`).
- Proven on 2026-11-24 by breaking each tool on purpose, one at a time: a magic number in `src/main` (Checkstyle), a method with 11 parameters (PMD `ExcessiveParameterList`) and an ignored `BigDecimal.add()` (SpotBugs `RV_RETURN_VALUE_IGNORED`) each fail the build.

## Amendment · Find Security Bugs (#205, 2026-11-27)

- **Decision:** SpotBugs also runs **Find Security Bugs** (`com.h3xstream.findsecbugs:findsecbugs-plugin` 1.14.0, version in `findsecbugs.version`), declared in the plugin's `<plugins>`. It adds about 140 OWASP-oriented detectors (injection, XSS, weak cryptography, unvalidated redirects, CSRF) to the analysis the build already runs, with the same policy: any warning fails `./mvnw verify`, and a false positive gets a narrow exclusion with its reason. It is a build-time dependency only: nothing reaches the jar. Chosen with the user while reviewing the project against the OWASP Top 10.
- **First run** (commit `3bc1cb9`), five warnings:

  | Pattern | Where | Outcome |
  | ------- | ----- | ------- |
  | `XSS_SERVLET` | `ApiSecurityConfig.writeProblem` | Fixed: the problem JSON was built with `String.formatted` without escaping; it is now serialized with Jackson (`ApiProblemResponsesTests`) |
  | `SPRING_CSRF_PROTECTION_DISABLED` | `ApiSecurityConfig` | Excluded: the API is stateless with Bearer tokens (ADR 0015), there is no cookie for a cross-site request to ride on |
  | `SPRING_CSRF_UNRESTRICTED_REQUEST_MAPPING` | `AccessDeniedController.forbidden` | Excluded: Spring Security forwards the 403 page with the original method; it changes no state |
  | `UNVALIDATED_REDIRECT` ×2 | `OAuth2LoginFailureHandler.onAuthenticationFailure` | Excluded: both targets are the context path plus a fixed path |

- **Alternatives:** OWASP Dependency-Check covers libraries, not our code (dependencies are covered by Dependabot and the `dependency-review` job, #204); Semgrep or CodeQL would add a second engine and its own rules for little gain on this code base.
- Proven by removing the `UNVALIDATED_REDIRECT` exclusion: `./mvnw verify` failed with both warnings, and passed again with it.

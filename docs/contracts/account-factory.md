# Contract: open an account through the factory

- **Issue:** [#18](https://github.com/dawnrock/Proyect-DDD-Claude/issues/18) · **Plan:** `docs/plans/2026-11-03-account-factory.md`
- **Status:** draft
- **Agreed by:** backend-dev, web-dev (rounds: —)

Replaces the open-account part of `open-query-list-accounts.md` (#5) and keeps the ownership rules of `login-roles.md` (#50). Querying and listing do not change.

## Application service

Phase 2: input port `com.pronoide.ddd.application.CheckingAccountCommands`, implemented by `CheckingAccountService`. The signature does not change; what changes is the command and the view.

```java
public interface CheckingAccountCommands {
    // Opens an account for command.ownerUsername() through CheckingAccountFactory: the IBAN is generated
    // (AccountNumberSequence) and the segment is decided from the holder's verified income (IncomeVerifier, R20).
    // Admin only.
    AccountSummary openAccount(Caller caller, OpenAccountCommand command);
}
```

## Commands (input)

Final shape (after T12):

| Command (`*Def`) | Field | Type | Required | Rules |
| ---------------- | ----- | ---- | -------- | ----- |
| `OpenAccountCommandDef` | `holderName` | `String` | yes | not blank |
| | `holderTaxId` | `String` | yes | Spanish NIF: 8 digits + a letter (`OpenAccountCommandDef.TAX_ID_PATTERN`); spaces and lowercase accepted, the domain (`TaxId`) normalizes them. The control letter is **not** checked |
| | `initialDeposit` | `BigDecimal` | yes | positive |
| | `currency` | `String` | no (default `EUR`) | ISO 4217 code |
| | `ownerUsername` | `String` | yes for `openAccount` | `OpenAccountCommandDef.USERNAME_PATTERN` (unchanged) |

Removed: `accountNumber` (generated by `AccountNumberSequence`) and `segment` (decided by the factory).

**Transition (expand → contract).** From T0 to T12 the command keeps `accountNumber` and `segment` as optional `@Deprecated` fields (default `""`, validated only if present) and `holderTaxId` is optional (default `""`, validated if present). Once the back opens through the factory (T5) it ignores the deprecated fields and requires `holderTaxId`. Neither side may rely on the deprecated fields in new code. T12 removes them and makes `holderTaxId` required in the command.

Violations throw `IllegalArgumentException` when the command is built (`@Value.Check`) → 400. Presentation validates first (below), so they should not reach the command.

### Shared presentation validation

The REST request (`OpenAccountRequest`) and the web form (`OpenAccountForm`) apply the same Bean Validation:

| Field | Constraint |
| ----- | ---------- |
| `holderName` | `@NotBlank` |
| `holderTaxId` | `@NotBlank` + `@Pattern(regexp = OpenAccountCommandDef.TAX_ID_PATTERN)` — message: "El NIF debe tener 8 dígitos y una letra" |
| `initialDeposit` | `@NotNull` + `@Positive` |
| `currency` | `@Pattern(regexp = "[A-Z]{3}")`, optional (`EUR`) |
| `ownerUsername` | `@NotBlank` + `@Pattern(regexp = OpenAccountCommandDef.USERNAME_PATTERN)` |

`accountNumber` and `segment` disappear from both.

## Errors

| Exception | When | Web (what the user sees) | REST (status + `ProblemDetail.title`) |
| --------- | ---- | ------------------------ | ------------------------------------- |
| Bean Validation | NIF, name, deposit, currency or user with a wrong format | back to the form with the field error | 400 + `errors` map by field |
| `IllegalArgumentException` | a command that skipped presentation validation | — | 400 |
| `InsufficientInitialDepositException` | deposit < 50.00 € (R1) | back to the form with the message | 422 |
| `CurrencyMismatchException` | deposit not in EUR | back to the form with the message | 422 |
| `DuplicateAccountNumberException` | the generator returned a number already in use (**safety net**, R16) | back to the form with the message | 422 |
| `ForbiddenOperationException` | a non-admin opens an account | access denied page | 403 |

An NIF the tax agency does not know is **not** an error: the account opens as `RETAIL`.

## REST (fragment of `docs/api/openapi.yaml`)

| Method and path | Request | Response |
| --------------- | ------- | -------- |
| `POST /api/accounts` | `OpenAccountRequest` (new body, incompatible change) | 201 + `Location` + `AccountSummary` (with `segment`) |
| `GET /api/accounts` | — | 200 + `AccountSummary[]` (now with `segment`) |

```yaml
OpenAccountRequest:
  type: object
  required: [holderName, holderTaxId, initialDeposit, ownerUsername]
  properties:
    holderName: { type: string, minLength: 1, example: Ada Lovelace }
    holderTaxId:
      type: string
      description: Spanish NIF (8 digits + a letter); spaces and lowercase are accepted. The control letter is not checked.
      pattern: '^ *\d{8} *[A-Za-z] *$'
      example: 12345678Z
    initialDeposit: { type: number, exclusiveMinimum: 0, example: 100.00 }
    currency: { type: string, pattern: '^[A-Z]{3}$', default: EUR }
    ownerUsername: { type: string, pattern: '^[a-z0-9._-]{3,30}$', example: ada }
AccountSummary:
  required: [id, accountNumber, holderName, segment, balance, currency]
  properties:
    segment: { type: string, enum: [RETAIL, HIGH_NET_WORTH], description: Computed by the factory from the verified income (R20). }
```

`AccountDetails` takes `segment` from `AccountSummary` instead of declaring it again.
